## Rules (in addition to `AGENTS.md`)

- **Gates run on the branch head and on the merge commit itself**, never on a parent. A merge-commit gate includes `make --jobs="$(nproc)" check` fully green with no waivers and `make compiler-perf` with the baseline named (the merge's first parent) and no slowdown beyond the noise floor with `MOSS_EST=off`.
- **No direct commits to `main`.** Doc-only commits are the one exception (`2120ab48`).
- **No timing studies.** compiler-perf is a slowdown guard only; shadow-mode overhead is recorded, never gated.
- **Shadow divergences** follow the three-outcome rule in `MOSS_LAZY_EXPRESSION_TREE.md` §4. "Existing-compiler inconsistency" is adjudicated by Bank against the language spec; the string path is a baseline, not the definition of Moss.
- **Reject, never copy.** If a lowering cannot be proved ownership-preserving, the program is rejected with a diagnostic. No `clone_if_needed`, no emitter-side fallback, no "temporary" string fallback.
- **Nothing is deleted in 27.1.** String parsers, the W1 cache and `*_by_context` maps are retired only after their last consumer migrates (27.2+), one at a time, each behind a green shadow gate.
- **Agent 2 is independent.** It does not read Agent 1's evidence before forming its probes; it reads the contracts and the checkpoint SHA. It records every attempted falsification, including the ones that failed to break anything.

## Stop rules (either agent: record in `.codex/CURRENT_STATUS.md`, push the branch, stop)

- A fix would change language semantics, the frozen ownership model, the `.mossi` format or the ABI beyond what the ownership doc already specifies.
- A shadow divergence cannot be classified after one honest investigation.
- An existing-compiler inconsistency needs a spec decision.
- An SDK library cannot be migrated without a language change.
- `make check` is not green after one honest attempt, or compiler-perf shows a slowdown beyond the noise floor on `off`.
- Agent 2 returns NO-GO.

For anything else, decide, write the decision and its reason in the status doc, and keep going.
