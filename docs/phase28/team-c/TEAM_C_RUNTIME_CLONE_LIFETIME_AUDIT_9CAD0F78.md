## Main disagreement with supplied matrix

The matrix correctly says the empty registry means no site is approved. It understates existing lifecycle evidence for runtime-03 and runtime-06: `check_phase20c_executor.py` test 39 measures exact strong counts for provider clone, ready-queue retention, join/removal and drop; it repeats 2,000 times and asserts all scopes are released. Tests 42, 46 and 47 additionally cover ready-queue bounds, saturation cleanup and the in-transit race. This is substantive behavioral evidence for those two sites, though it still does not encode exact source-site provenance in the frozen clone registry/sidecar.

The matrix's runtime-02 “not a Moss value” assessment is supported for current Moss call paths: `MossExecutor::config()` is absent from the compiler-recognized Moss config-method set and generated Moss source only configures then consumes the builder with `.start()`. But the field being cloned is a `Vec<usize>` created from Moss `affinity(Vector[Int])` configuration. Treat this as a runtime config snapshot with source-derived contents; do not generalize its classification to arbitrary Vec clones.

## Minimal adversarial validation proposal

Use exact per-site IDs and source digest/span in provenance evidence. Each mutation must fail closed: missing, duplicate, moved marker; wrong site/type/source digest; stale or extra sidecar/registry row. Do not add a family-wide Arc/Vec exception.

1. **Process executor snapshots (01/09/11):** force interleavings for `branch_publish`/`branch_join` and `runtime_invoke` around start, ACTIVE admission, DRAINING and join; assert progress without process lock held across executor work, no use-after-free, and executor Arc drops after all local/slot/worker owners leave.
2. **Fair lock node and condvar waiter (04/05):** deterministic three-contender FIFO schedule with both guard-drop branches (tail CAS success and successor already swapped); force `notify_one`, `notify_all`, and unrelated/spurious unpark. Assert each waiter completes once, no lost wakeup, and per-node/per-waiter strong/drop counts return to zero.
3. **Branch scope / queue (03/06):** retain existing test 39 exact refcount, stress, and leak assertions; pin generated runtime marker/type at both FFI clone and ready-queue clone. Keep tests 42/46/47 and corruption/drop/duplicate identity checks.
4. **Worker executor lifetime (08):** normal shutdown, worker panic/unwind and spawn failure; assert the worker guard keeps executor alive while accessing it and releases one count on every exit.
5. **Reply slot (10):** non-Clone reply type with unique ID and Drop counter under concurrent ACTIVE Roots and INLINE; assert one write, one take and one drop per reply, and no cross-caller reply mixup.
6. **Config snapshot (02):** source path with `affinity([..])` should verify conversion to runtime indices; Rust API test snapshots builder config, derives a changed builder afterward, proves snapshot isolation, and confirms `.config()` remains unavailable from Moss. Preserve no generic Moss collection-copy authority.

## Overall conclusion

For nine Arc sites, source types and operations show strong-reference handle duplication, not Moss payload cloning. Runtime-03 and runtime-06 also have direct exact-reference-count stress evidence. Runtime-02 is a deep clone of an owned runtime `Vec<usize>` config snapshot; it is not an exposed Moss `.config()` operation, but the source-derived affinity boundary should stay explicit. Across all ten, exact callsite provenance remains **unapproved** because the frozen registry is empty and the marker/inventory does not itself encode a reviewed exception. No site is shown removable without changing current synchronization, lifetime or owned-snapshot behavior; runtime-02 is the only one with a plausible API-level restructure option, which needs an explicit Rust API decision.

The FileIO (`fileio_runtime.cpp:1293`) and FileChunk (`file_chunk_codegen.inc:238`) Arc sites are not among these ten and were not approved or reclassified here; the matrix correctly requires separate focused artifacts for them.
